13.2 discretization selection index

See Section 9.1 for a worked comparison in this layer.

count. Validate integer controls before building a declaration. For example, count(cells, "cells", minimum=2) returns the integer or raises ValueError. Example in Section 9.1.2.

Numerics. Compose independent spatial, linear, nonlinear, time, and coupling selections. Initial guesses and scales are mappings keyed by owned field references. Example in Section 9.9.1.

NumericalExecutionPlan. Inspect resolved bindings and provider_for(...) after numerical resolution. Use to_dict() to serialize the resolved record. Example in Section 10.1.1.

NumericalIR. Inspect equation, field and capability requirements before provider resolution. Use its mapping and content fingerprint for diagnostics. Example in Section 10.1.1.

NodalInterpolation. Evaluate initial values at native nodes through the spatial initialization port. Example in Section 9.1.1.

CellAverageProjection. Initialize FV cell means by physical volume quadrature. Set quadrature_order when the model needs a different rule. Example in Section 10.2.18.

L2Projection. Project initial values by the supported mass solve with a selectable quadrature order. Example in Section 9.1.1.

LumpedParameters. Choose the zero-dimensional spatial contract for a LumpedMesh. Optional collaborators supply stability or algebraic operations. Example in Section 9.9.1.

OperatorConditions. Implement the structural condition-evaluation interface when binding a custom spatial operator. The operator owns the physical boundary support and receives evaluation time. Example in Section 10.1.2.

OperatorFacetTopology. Implement the facet-topology interface when a custom operator needs to expose physical face IDs, orientations and boundary membership. Example in Section 10.1.2.

EvaluationCacheControl. Expose the evaluation-cache lifecycle on a bound operator when its residual or tangent reuses geometry-dependent data. Example in Section 10.1.2.

NumericalCompatibilityError. Exception with a machine-readable rejection kind, rejected option and required capabilities. Example in Section 10.1.1.

MethodProviderOffer. Pass a provider's actual capability offer to compatibility evaluation. Availability and diagnostics describe the supplied context. Example in Section 9.1.2.

evaluate_method_provider. Compare the supplied provider's offer against method requirements and any additional requirements. Returns a compatibility report. Example in Section 9.1.2.

CapabilitySet. Describe the feature and guarantee identifiers offered by a provider. Example in Section 9.1.2.

RequirementSet. Specify required and preferred feature identifiers for compatibility checks. Example in Section 9.1.2.
