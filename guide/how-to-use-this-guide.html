How to use this guide

The workflows in Part I follow the same sequence as the shipped notebooks. State the physical question and units, assemble the model, choose numerical methods, solve, check the solution, and build the figure from the checked data. Start with the lumped cooling example to learn the execution path and then choose a spatial example. Part II gives a starting model, numerical route, and verification target for every physics package. Part III explains the role of each numerical layer and how to combine declarations. The appendices give the import names, signatures and contracts for the canonical exports. Chapter 6 expands the physics and service examples. Chapter 9 provides controlled method comparisons, and Chapter 13 locates each numerical symbol in the workflows or source tests.

The reference covers onesim.physics, its sixteen domain packages, onesim.numerics and its nine method packages. Publicly exposed operator namespaces are identified separately. The reference boundary is the application-facing package exports. Backend implementation modules, compatibility aliases, commercial product services and internal helper functions have separate ownership and can change with the runtime. An exported configuration, protocol or result adapter is a contract. Its presence says nothing about which physical model, mesh and solver combinations the installed runtime can execute. The examples and cited source tests specify concrete combinations.
